# Contributing to Card-Sharp

Thanks for helping improve Card-Sharp.

## Before opening a pull request

1. Keep changes scoped and preserve the rule-aware strategy behavior.
2. Run `python -m card_sharp.self_test` from the project virtual environment.
3. Do not commit `venv/`, `build/`, `dist/`, database files, or macOS Finder metadata.
4. Explain the casino rule source for any preset change. Casino conditions vary by table, limit, and time, so all presets must remain editable and accurately qualified.

## Bug reports

Include macOS version, app version, the selected rules preset, exact steps, and the expected versus actual behavior. Never include personal database files or other sensitive data.
